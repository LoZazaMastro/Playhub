# GPU mirror component: inactive TEMP port

This is a source-compatible first unit for the native Steam companion. No application Source, installed file or live window was changed. It contains an actual Win32 destination and DWM thumbnail backend, an independent authenticated lifecycle, and a readonly native V1 snapshot. It is not activated or wired to SteamCompanion yet. No claim is made that this component alone solves input or proves changing Valve pixels.

The destination is created in the same companion process, initially hidden. After the existing exact-window band16 broker has completed and revoked its one operation, the owner sizes the destination to the physical monitor rectangle of the exact authenticated game window, read with MonitorFromWindow/GetMonitorInfo. It uses BLACK_BRUSH/zero-black backing and DwmExtendFrameIntoClientArea with negative margins. DWM attaches the actual companion source HWND to that destination, on the GPU. There is no BitBlt, desktop screenshot, game snapshot, CPU pixel buffer, image fallback, DwmFlush loop, foreground API, key injection or automatic Steam command. DWM updates the registered thumbnail independently. Visual alpha remains an actual root test, not a consequence of a successful API return.

`Presentation::Begin` only accepts a current trusted issuer lease and strictly newer generation. It can wait for the native band operation. Every transition rechecks authority, native context and the real expiry after native calls. Completion of the band broker and GPU attachment produces Prepared with the destination still hidden. Prepared is a current authenticated composition fact suitable for the separate scoped SetOverlayState(gameid,2) bootstrap, without requiring scope2. It is neither a verified-pixel nor input authority. ShowPrepared additionally requires the same session/generation and a separate trusted RendererReady receipt; only that explicit step can show the destination. Set2 failure or cancellation must call Close. A cancel during create/attach/show cannot publish a late valid lease or re-show after cleanup. `Renew` changes only expiry for the exact same immutable authority; expired authority cannot be resurrected. There is no maximum number of reopens or diagnostic session TTL. Session duration and renewal cadence belong to the authenticated issuer. `Close` immediately revokes the readonly lease, then hides and unregisters. A failed hide or uncertain callback retirement returns CleanupPending, not success. Cleanup-only Tick may be called until complete, never admitting new work. Normal Closed Tick does no source polling.

The native runtime retains game/frame process handles and checks PID+birth, same user/session, exact current game HWND/thread/rectangle/desktop/foreground and exact own source class/thread/root/cookie/rectangle/band. Binding an ApplicationFrameHost to the real game/AUMID is the trusted issuer's job; the backend does not guess that association. Only the current companion-owned `PlayhubSteamCompanion` source is accepted. The mirror reports scope1 while the real game remains foreground and never invents scope2 or keyboardAt. An observed attachment is not an input/layout authorization.

`ReadPresentationSnapshot` is readonly and fixed-version/size checked. It publishes sessionId hex64, full unsigned CGameID, generation/expiry, source/destination HWND/cookie, owner/game PID+birth, state and observed attachment facts. `observedAt` is the last owner-thread publication. `readAt` is the read clock. An expired read invalidates leaseCurrent/scope without claiming the last-visible HWND has physically disappeared. `pixelsVerified` and `inputAuthority` stay false. All clock values are Windows GetTickCount64 milliseconds of the current boot in this same companion; the snapshot is not persistent authority across process/boot changes.

## Band16 boundary

`IBand16Broker` is explicit and has NO permissive/default implementation. The actual runtime always requires the real native destination band16 readback. The original C449 reference remains immutable under callback-reference. The actual callback-v3 source/license/build recipe are included separately and produce a new PlayhubExactBand DLL with a generated exact digest in the client library. That callback requires a signed/exact Explorer process/thread, same user/session/desktop, nonce-bound own hidden target, and a true UWP/AFH game proof. It only makes its single band write after commit and checks again after slow getters. Its transaction budget is a security bound, not the mirror session duration. It supports a distinct retained Win32 branch: exact game PID/birth/image/class/thread/rectangle, real non-AppContainer token with same user/session/integrity, clean desktop and exact actual foreground; no fabricated AppContainer or generic foreground allow. UWP keeps its exact original AFH/CoreWindow/package/AUMID branch. No extra hook or privilege is proposed.

The in-process broker now implements that real in-process client: pinned callback and private nonce copy, signed Explorer path/PID/birth/thread and SID/session checks, exact UWP/AFH source, shared wire mapping/event with current-user security, nonce-bound WH_CALLWNDPROC and WM_NULL, actual callback identity/receipt/band16 readback, revocation/unhook/quiescence and stable module absence. It never calls Proof.exe or starts Explorer. It returns Pending while committed/retirement is uncertain. The same fixed callback transaction security bound is retained; it is unrelated to the renewable mirror session. The new callback-v3 PlayhubExactBand DLL is not loaded at library initialization. The library is not yet linked into the live SteamCompanion callsite or status pipe.

If native cleanup is uncertain, the backend keeps its exact hidden native state in a process-lifetime retirement list. DrainRetainedMirrorCleanup must run on the original GUI thread until complete. No mutex is held across cleanup native calls, to permit message reentrancy. The host must keep that GUI thread/process alive while committed callbacks remain; process termination cannot guarantee HWND lifetime and must never be represented as clean teardown. It must not unload the code while native windows remain. This obligation is explicit, not a promise that a destructor can keep a process alive.

## Integration contract with the pad issuer

The issuer authenticates its original Guide and retained game/session/presentation identity; Begin/Renew/Close are internal calls only, not a standalone public authorization endpoint. Source expiry must also govern the scoped Valve foreground view. On Back/close/AltTab/disconnect/replacement/unload, revoke presentation and call Close first. The separate pad issuer owns its own release/restore0 acknowledgement and released-sample gate; a mirror snapshot cannot authorize forceinputappid769 or prove that the game stopped receiving input. No input path is implemented by this library.
